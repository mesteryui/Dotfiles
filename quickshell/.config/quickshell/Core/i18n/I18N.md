# i18n

Files: `en_US.json` (reference, always complete), `es_ES.json`,
`eo.json`. Same 16 top-level sections in all three (258 keys in
`en_US`): `battery`, `cheatsheet`, `launcher`, `lockscreen`,
`media`, `notifications`, `osd`, `panel`, `polkit`, `power`,
`settings`, `sysmenu`, `updates`, `wallpaper`, `weather`,
`switcher`.

Conventions:

- Keys are dotted paths: `section.name`, e.g. `launcher.placeholder_all`,
  `settings.interface.bar.height`, `sysmenu.about_title`.
- Placeholders use `%1`, `%2` (battery, updates).
- `titleKey`/`subtitleKey` in launcher menus resolve through the same
  dictionary (see `Launcher/GUIA-MENUS.md` §6).
- QML call sites pass a Spanish inline default;
  `I18nService.getTranslation(key, default)` falls back per-key:
  loaded language → `en_US` file → inline default. Keep `en_US`
  complete and add new keys there first. The English fallback file
  is only loaded when the candidate is not English
  (`needFallbackFile`); otherwise `translations` already is `en_US`.

Language resolution (`I18nService`):

- `configs.language` (`userDefinedLang`) wins when set; otherwise
  `Qt.locale().name` (`systemLang`).
- Normalization: `es_*` → `es_ES`, `en_*`/`en` → `en_US`; any other
  locale loads verbatim (`eo` → `eo.json`).
- Missing file → whole-file fallback to `en_US` (console warns);
  missing key → per-key fallback to the `en_US` value
  (`fallbackTranslations`).

Adding a locale:

1. Copy `en_US.json` to `<lang>.json` (use `Qt.locale().name` form,
   e.g. `fr_FR.json`).
2. Translate values, keep keys and `%1` placeholders.
3. If the locale needs aliasing (like `es_*`/`en_*`), add it in
   `I18nService.candidateLang`.
4. Missing file → whole-file fallback to `en_US`;
   missing key → per-key fallback to `en_US` value.
